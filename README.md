# amnezia-autoupdate

Скрипт для VPS с Amnezia VPN. Ставится на сервер один раз и дальше каждую ночь сам:

* обновляет пакеты ОС и перезагружает сервер, если этого требует новое ядро;
* обновляет контейнеры Amnezia (AmneziaWG, XRay, WireGuard, AmneziaDNS) до последнего релиза
  приложения Amnezia, **сохраняя ключи сервера и всех пользователей**: выданные конфиги продолжают работать;
* чистит старые образы Docker и кэши, чтобы не забить маленький диск.

Ещё он умеет развернуть протоколы на чистом сервере и перенести базу пользователей с одного
сервера на другой. Всё делается теми же серверными скриптами, которыми пользуется само
приложение Amnezia, поэтому сервер по-прежнему управляется из приложения: пользователей
добавляешь и удаляешь там, как раньше.

Если подключить бота Telegram, он присылает отчёты об обновлениях и по команде `/status`
показывает состояние сервера (см. [Telegram](#telegram-отчёты-и-команда-status)).

## Установка

Зайди на сервер по ssh и выполни:

```bash
curl -fsSLO https://raw.githubusercontent.com/iF-22/amnezia-autoupdate/main/amnezia-autoupdate
sudo bash amnezia-autoupdate install
```

Установщик кладёт скрипт в `/usr/local/sbin/amnezia-autoupdate`, создаёт настройки
`/etc/amnezia-autoupdate.conf`, включает ежедневный таймер (по умолчанию в 04:00 по Москве
плюс случайная задержка до 30 минут) и в конце показывает, что будет обновлено. Сам при
установке он ничего не пересобирает.

Полезные параметры `install` (их можно добавить и при повторном запуске, настройки сохранятся):

| Параметр | Что делает |
|---|---|
| `--time 04:00 --tz Europe/Moscow` | время ежедневного обновления и часовой пояс |
| `--delay 30min` | случайная задержка, чтобы серверы не перезагружались одновременно |
| `--reboot if-needed\|never\|always` | когда перезагружать (по умолчанию только если нужно) |
| `--no-os-update` | не трогать пакеты ОС, обновлять только Amnezia |
| `--telegram-token ТОКЕН --telegram-chat ID` | присылать отчёты в Telegram и отвечать на `/status` |
| `--telegram-commands no` | только отчёты, на команды в Telegram не отвечать |
| `--name ИМЯ` | имя сервера в отчётах |
| `--deploy awg,xray` | сразу развернуть протоколы (для чистого сервера) |
| `--import ФАЙЛ` | сразу поднять контейнеры из архива экспорта |
| `--update-now` | после установки сразу обновить всё (без перезагрузки) |
| `--journal-max 200M` | ограничение системного журнала (`0` = не трогать) |

## Три сценария

### 1. Сервер уже настроен приложением Amnezia

Просто установи скрипт, как выше. Он подхватит контейнеры, которые поставило приложение,
и ночью обновит те, для которых вышли новые версии. Чтобы обновить сразу:

```bash
sudo amnezia-autoupdate run --no-reboot
```

### 2. Чистый сервер

```bash
sudo bash amnezia-autoupdate install --deploy awg,xray
```

Поставит Docker и протоколы так же, как это делает приложение: AmneziaWG версии 3.1
(контейнер `amnezia-awg2`, как в последнем приложении) на порту 55424/udp и XRay VLESS REALITY
на 443/tcp. Порты можно поменять: `--awg-port 51888 --xray-port 8443`,
сайт для маскировки XRay: `--xray-site www.example.com`. Можно добавить `wireguard` и `dns`.

Потом в приложении Amnezia добавь сервер: IP, логин и пароль. Отдельной настройки для SSH-ключа
в приложении нет, но в поле «Пароль или приватный SSH-ключ» можно вставить сам ключ целиком,
вместе со строками BEGIN и END (приложение принимает ED25519 и RSA в формате PEM).
Приложение найдёт установленные протоколы само, дальше всё как обычно.

### 3. Перенос пользователей на другой сервер

На старом сервере:

```bash
sudo amnezia-autoupdate export
# архив: /root/amnezia-export-ИМЯ-ДАТА.tar.gz
```

Скопируй архив на новый сервер (например `scp`) и там выполни:

```bash
sudo bash amnezia-autoupdate install --import /root/amnezia-export-ИМЯ-ДАТА.tar.gz
```

Переносятся ключи сервера, все пользователи с их именами из приложения, параметры
маскировки AmneziaWG и порты. **В архиве приватные ключи, храни его как пароль.**

* **Тот же IP** (например, переустановил ОС на том же VPS): у пользователей всё работает
  без изменений. На своём компьютере выполни `ssh-keygen -R IP_СЕРВЕРА`, иначе ssh будет
  ругаться на смену ключа хоста. Приложение Amnezia ключ хоста не проверяет, поэтому если
  пароль или SSH-ключ для входа остались прежними, в приложении ничего делать не нужно,
  и полный доступ, которым ты делился, тоже продолжит работать. Если пароль сменился, выбери
  в настройках сервера «Удалить сервер из приложения» (протоколы на сервере останутся),
  добавь сервер заново с новым паролем и заново поделись полным доступом, если делился.
* **Новый IP**: в выданных конфигах записан старый адрес, поэтому пользователям понадобятся
  новые конфиги. Исключение: если сервер добавлен в приложение по доменному имени, достаточно
  перенаправить домен на новый IP.

## Как устроено обновление контейнера

1. Скрипт берёт серверные скрипты последнего релиза
   [amnezia-client](https://github.com/amnezia-vpn/amnezia-client/tree/dev/client/server_scripts).
   Контейнер обновляется, если в релизе изменился его Dockerfile или вышел новый базовый образ
   (например `amneziavpn/amneziawg-go`).
2. Новый образ собирается, пока старый контейнер работает. Перед этим проверяется место на
   диске, при нехватке сначала чистится кэш.
3. Новый образ проверяется до остановки старого (например, что XRay принимает текущий
   `server.json`).
4. Старый контейнер останавливается, его `/opt/amnezia` (ключи, пользователи, clientsTable,
   start.sh) копируется в резервную копию и переносится в новый контейнер. VPN недоступен
   несколько секунд, клиенты переподключаются сами.
5. Проверка: интерфейс поднят, порт и ключ сервера прежние, пользователей не меньше, чем было.
   Если что-то не так, возвращается старый контейнер, а в отчёте будет ошибка.

Если сервер выключится посреди обновления, при следующей загрузке старый контейнер вернётся
сам. Резервные копии лежат в `/var/backups/amnezia-autoupdate` (по 10 последних на каждый контейнер).

Если в новом релизе приложения серверные скрипты изменились так, что скрипт их не понимает
(новые параметры, не только команды docker), он ничего не трогает и пишет об этом в отчёте.

Важно: **не меняй в приложении серверные настройки AmneziaWG и WireGuard** (порт, подсеть,
Jc, S1, H1 и остальные) и не удаляй эти протоколы, чтобы поставить заново. Приложение при этом
пересоздаёт контейнер с новыми ключами сервера, и все выданные конфиги перестают работать.
Перед сохранением оно об этом предупреждает: «Все пользователи, с которыми вы поделились
конфигурацией вашего VPN, больше не смогут к нему подключаться». Это касается и тех, с кем ты
поделился полным доступом к серверу. Добавлять и удалять пользователей можно как обычно,
а обновлять контейнеры теперь будет этот скрипт.

## Команды

| Команда | Что делает |
|---|---|
| `sudo amnezia-autoupdate status` | контейнеры и клиенты, последний и следующий запуск, место на диске (то же, что `/status` в Telegram) |
| `sudo amnezia-autoupdate check` | показать, что будет обновлено, ничего не меняя |
| `sudo amnezia-autoupdate run [--no-reboot] [--no-os]` | полный цикл прямо сейчас (так запускает таймер) |
| `sudo amnezia-autoupdate update-containers [--force] [--only amnezia-awg2]` | только контейнеры |
| `sudo amnezia-autoupdate update-os` | только пакеты ОС, без перезагрузки |
| `sudo amnezia-autoupdate deploy awg,xray` | развернуть протоколы |
| `sudo amnezia-autoupdate export [ФАЙЛ]` | сохранить ключи и пользователей в архив |
| `sudo amnezia-autoupdate import ФАЙЛ` | поднять контейнеры из архива |
| `sudo amnezia-autoupdate backups` | список резервных копий |
| `sudo amnezia-autoupdate restore amnezia-awg2 [ДАТА]` | вернуть ключи и пользователей из копии |
| `sudo amnezia-autoupdate self-update` | скачать новую версию скрипта с GitHub |
| `sudo amnezia-autoupdate uninstall [--purge]` | убрать таймер и бота (контейнеры не трогаются) |

### Журнал

Журнал: `/var/log/amnezia-autoupdate.log` или `journalctl -u amnezia-autoupdate`. Он циклический:
когда файл больше 10 МБ (`LOG_MAX_MB`), самые старые записи отрезаются. Так выглядит ночь,
когда обновлять нечего:

```text
2026-11-11 04:17:32 === amnezia-autoupdate 1.2.0: запуск по расписанию на vps1 ===
2026-11-11 04:17:32 ОС: Ubuntu 24.04.3 LTS, ядро 6.8.0-87-generic
2026-11-11 04:17:32 обновляю пакеты ОС
2026-11-11 04:17:58 ОС: обновлений нет
2026-11-11 04:17:59 серверные скрипты Amnezia: релиз 5.1.0.6
2026-11-11 04:18:00 amnezia-awg2: актуален (amneziawg-go 0.0.20250522, awg 3.1.20260812, релиз Amnezia 5.1.0.6)
2026-11-11 04:18:00 amnezia-xray: актуален (xray 26.10.31, релиз Amnezia 5.1.0.6)
2026-11-11 04:18:01 сетевые настройки хоста применены (setup_host_firewall.sh, лог: /var/lib/amnezia-autoupdate/host-setup.log)
2026-11-11 04:18:01 === итог: ok, всё актуально, обновлять нечего, заняло 29 с ===
```

Если обновление есть, вместо «актуален» будет причина («нужно обновление: новый Dockerfile» или
«новый базовый образ»), шаги сборки и замены контейнера и строка с версиями до и после, например
`amnezia-xray обновлён до релиза Amnezia 5.1.1.0 (новый Dockerfile); было: xray 26.10.31; стало: xray 26.11.20; клиентов: 2`.
Для ОС пишется, сколько пакетов обновлено, и какие именно. Итог: `=== итог: ok, изменений: 1, заняло 58 с ===`.

## Настройки

Все настройки в `/etc/amnezia-autoupdate.conf`, в файле есть пояснения. Основные:

* `OS_UPDATE`, `CONTAINERS_UPDATE`: что обновлять (`yes`/`no`).
* `REBOOT`: `if-needed`, `never` или `always`.
* `UPSTREAM_REF`: `latest` или конкретный релиз приложения, например `5.1.0.6`.
* `KEEP_BACKUPS`, `MIN_FREE_MB`: сколько копий хранить и сколько места нужно для сборки.
* `LOG_MAX_MB`: размер журнала в МБ (по умолчанию 10), сверх него отрезаются самые старые записи.
* `NOTIFY`: когда писать в Telegram: `changes` (изменения и ошибки), `errors`, `always`, `never`.
* `TELEGRAM_COMMANDS`: отвечать ли на `/status` в Telegram (`yes`/`no`).

После смены времени запуска или настроек Telegram выполни `sudo amnezia-autoupdate install` ещё
раз: он обновит таймер и перезапустит бота.

### Telegram: отчёты и команда /status

1. В Telegram напиши [@BotFather](https://t.me/BotFather) команду `/newbot` и получи токен.
2. Напиши своему боту любое сообщение.
3. Открой `https://api.telegram.org/botТОКЕН/getUpdates` и найди `"chat":{"id":...}`. Если этот бот
   уже стоит на другом сервере, список будет пустым (сообщения забирает тот сервер), но ID тот же,
   что ты указал там.
4. `sudo amnezia-autoupdate install --telegram-token ТОКЕН --telegram-chat ID`

В конце установки бот пришлёт в чат проверочное сообщение. Если не пришло, install напишет
почему: Telegram не принял токен или бот не может написать в этот чат.

**Отчёты** приходят после ночного обновления. По умолчанию (`NOTIFY=changes`) только когда что-то
обновилось или случилась ошибка, поэтому в спокойную ночь сообщения нет. Чтобы отчёт приходил
каждую ночь, поставь `NOTIFY="always"` в `/etc/amnezia-autoupdate.conf`.

**Команда /status** в любой момент присылает то же, что `sudo amnezia-autoupdate status`:

```text
[vpn] amnezia-autoupdate 1.2.0
Контейнеры:
  amnezia-awg2: работает, клиентов: 2, на связи: 1
    amneziawg-go 0.0.20250522, awg 3.1.20260812; обновлён 2026-11-14 17:52 MSK (релиз 5.1.0.6)
Последний запуск: 2026-11-14 17:52 MSK, итог: ok
  Изменения:
  • amnezia-awg2 обновлён до релиза Amnezia 5.1.0.6 (принудительно); версии те же: amneziawg-go 0.0.20250522, awg 3.1.20260812; клиентов: 2
Следующий запуск: 2026-11-15 04:12 MSK (через 10 ч 20 мин)
Скрипты Amnezia: релиз 5.1.0.6
Свободно на диске: 4210 МБ
Нужна перезагрузка: нет
Сервер запущен 1 ч 5 мин назад
```

«На связи» значит, что клиент обменивался ключами с сервером в последние 3 минуты. Время
показывается по часовому поясу расписания (`UPDATE_TZ`).

Бот отвечает только в чат `TELEGRAM_CHAT_ID`, сообщения из других чатов он молча пропускает.
Команды слушает служба `amnezia-autoupdate-bot` (журнал: `journalctl -u amnezia-autoupdate-bot`).
Она только читает состояние сервера: ничего не меняет, на VPN и ночное обновление не влияет,
памяти ей отведено не больше 128 МБ. Только отчёты, без команд:
`sudo amnezia-autoupdate install --telegram-commands no`.

**Несколько серверов.** Можно завести отдельного бота на каждый сервер (у каждого свой чат,
ответ приходит сразу), а можно один бот на все: ID чата у всех серверов будет один и тот же.
Telegram отдаёт сообщения бота только одному получателю, поэтому серверы с общим ботом сами
это замечают и переходят на общий режим: на `/status` отвечает каждый, в течение 20 секунд,
а `/status ИМЯ` спрашивает только сервер с этим именем (`--name` при установке или hostname).

## Что поддерживается

* ОС: Ubuntu 22.04, 24.04, 26.04, Debian 12, 13. На AlmaLinux скрипт установки Docker из
  приложения не работает (там вместо Docker podman), её лучше не брать.
* Контейнеры: `amnezia-awg2` (AmneziaWG, его ставит текущее приложение), `amnezia-awg`
  (в приложении называется AmneziaWG Legacy, его скрипт только обновляет, если он уже стоит),
  `amnezia-wireguard`, `amnezia-xray`, `amnezia-dns`. Остальные (OpenVPN, IPsec, MTProxy, SOCKS5, SFTP, Tor-сайт)
  скрипт не трогает, их обновляй через приложение.
* Переход на новую версию ОС (например 22.04 на 24.04) скрипт не делает, только обновления
  внутри текущей версии.
* Диск: для сборки образа нужно около 1,5 ГБ свободного места. Скрипт чистит старые образы,
  кэш сборки Docker и apt, а системный журнал ограничивает 200 МБ.

## Проверка

`tests/e2e.sh` разворачивает протоколы настоящими скриптами приложения, добавляет
пользователей так же, как приложение, и проверяет обновление, откат, восстановление после
обрыва, экспорт и импорт. **Запускать только на одноразовой машине**, тест удаляет контейнеры
Amnezia:

```bash
git clone --depth 1 https://github.com/amnezia-vpn/amnezia-client
sudo bash tests/e2e.sh amnezia-client/client/server_scripts
sudo bash tests/install.sh
sudo bash tests/bot.sh
```

`tests/bot.sh` проверяет бота Telegram на заглушке Bot API (`tests/telegram-mock.py`): кому он
отвечает, что не отвечает дважды, общий бот на два сервера, ошибки Telegram. Ему не нужны
ни Docker, ни настоящий бот.

Те же тесты запускаются в GitHub Actions при каждом изменении и раз в день на последнем
релизе приложения Amnezia (вкладка Actions). Если очередной релиз окажется несовместим со
скриптом, это будет видно там, а серверы в такой ситуации ничего не ломают: либо не трогают
контейнер, либо возвращают прежний и сообщают об ошибке.
